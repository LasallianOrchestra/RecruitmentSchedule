Make the LSO Scheduler Live with Supabase

This version uses Supabase for the shared PostgreSQL database, anonymous visitor sessions, database security, conflict prevention, and live calendar updates across phones, tablets, laptops, and desktops.

1Create your Supabase project

Create a project in the Supabase dashboard. After the project is ready, keep the dashboard open for the next steps.

2Enable Anonymous Sign-Ins

Open Authentication in Supabase and enable Anonymous Sign-Ins. The scheduler uses an anonymous authenticated session so visitors do not need to create a visible account, while Row Level Security can still identify who created a booking.

A booking can only be cancelled from the anonymous browser session that created it. Clearing browser storage or using another device creates a different anonymous identity.

3Create the database and security rules

Open SQL Editor, create a new query, paste the entire contents of supabase-setup.sql, then click Run.

That script creates public.recruitment_bookings, enforces APPLICANT-only 60-minute interviews from 10:00 AM through the 4:00 PM start slot, enables RLS, limits cancellation to the creator, creates the unique date/hour conflict rule, and adds the table to Supabase Realtime.

4Add your Project URL and Publishable Key

In the Supabase dashboard, copy your Project URL and browser-safe Publishable Key. Open supabase-config.js and replace the placeholders:

window.LSO_SUPABASE_CONFIG = {
  url: "https://YOUR_PROJECT_REF.supabase.co",
  publishableKey: "sb_publishable_YOUR_KEY"
};

Never put a Supabase Secret Key or service_role key in this website. Those keys bypass Row Level Security. The browser should only receive the Publishable Key (or a legacy anon key).

5Test live synchronization

Serve or upload the website, then open it on two devices or two separate browser profiles. Book a slot on one device. The second open calendar should receive the database change and refresh automatically.

If two people attempt the exact same date and hour at nearly the same time, the PostgreSQL unique index allows only one row. The other booking receives a conflict message and is rejected.

6Publish the frontend

Supabase is the backend for this package. Upload the website files to any static HTTPS host, including Netlify, Vercel, Cloudflare Pages, GitHub Pages, or an existing domain/web host. There is no build command required.

Upload at minimum: index.html, styles.css, app.js, supabase-config.js, manifest.webmanifest, service-worker.js, and the assets folder.

What “live” means in this version

  • All visitors read the same Supabase table.
  • New bookings are synchronized through Supabase Realtime.
  • Calendar availability updates without manual refresh while the page is connected.
  • Database constraints, not just browser JavaScript, protect against duplicate slots.
  • Row Level Security protects create/delete actions.

When the status pill says “Live sync connected,” the page is using Supabase rather than device-only preview storage.
